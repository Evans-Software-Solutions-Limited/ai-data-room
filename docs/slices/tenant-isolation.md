## How to read this doc

Each row maps a requirement to its **implementation site** (the production
code that satisfies it), its **verification** (what the test asserts), and the
**test file** that runs in CI. Rows are honest — a partially-covered or
deferred requirement says so out loud rather than inventing coverage.

The slice is a cross-cutting hardening layer with almost no user-visible
surface: its deliverable is the _mechanism_ (a mandatory `scopedRepo(orgId)`
factory) plus the _proof_ (a property test) that no query under one org's
scope can return another org's rows.

## Non-functional requirements (NFR)

| Req      | Summary                                                                                                         | Status / evidence                                                                                                                                                                                                                                                                                                                                                    |
| -------- | --------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **NFR1** | No cross-tenant leak — the load-bearing invariant, proven by a property test.                                   | ✅ `tenantIsolation.property.integration.test.ts` (T-006): `fast-check` over real Postgres, two orgs, random distributions, every scoped-read method under org A asserts zero org-B (and zero null-org) rows. Revert-checked (drop a predicate → fails + shrinks).                                                                                                   |
| **NFR2** | Tenant guard adds ≤2ms p95 overhead per query.                                                                  | ⚠️ **Not separately benchmarked.** The guard adds a single indexed `WHERE org_id = $1` predicate (and existing `(org_id, …)` btrees already cover the hot paths), so the overhead is a query-planner-level constant, not a round-trip. A formal p95 micro-benchmark is deferred — no measurable regression is expected or observed in the integration suite timings. |
| **NFR3** | Composes with the `withTx(tx)` transaction pattern.                                                             | ✅ `ScopedRepo.withTx` returns a same-org tx-bound instance; the factory's `withTx` rebinds the whole bundle. `acceptInvitation` (`scopedRepo(invitation.orgId, tx)`) and `createOrg` (`scopedRepo(org.id, tx)`) exercise it end-to-end. `scoped.test.ts` + the invitation/createOrg suites.                                                                         |
| **NFR4** | Composes with the `ai-search-qna` pgvector ANN double access-filter (SQL tenant predicate is the first filter). | ➖ **Forward-looking** — pgvector + ANN retrieval land in `ai-search-qna` (slice 6). The design keeps the door open (the `scoped()` predicate is a plain `WHERE` AND-able into any query, including the ANN filter); no pgvector code exists yet to test.                                                                                                            |
| **NFR5** | Architecture must not preclude a later move to Postgres RLS (ADR-011 Option A).                                 | ✅ Architectural — the registry enumerates every scoped table and the factory funnels every access through one place, so an RLS rollout is mechanical. Documented in [ADR-011 §Consequences](../../adr/011-multi-tenant-isolation.md). RLS revisited before SOC 2.                                                                                                   |

## Coverage gaps / deferred (honest register)

- **FR8 audit-writer emission → [T-009](../../.kiro/specs/ai-data-room/tenant-isolation/tasks.md).** The runtime catch's operator signal (metric + log + `> 0` alarm) ships in T-007; the audit _event_ (actor-tagged, via the app-layer writer) is deferred to an application/webhook error boundary because `stampOrgId` is infrastructure and must not import the application-layer audit writer. Trigger is a should-never-happen programming bug already covered by the alarm.
- **FR5 cross-org admin API** — no such operation exists in this slice; owned by `admin-dashboard` (slice 7), which must define its own explicit non-factory API.
- **NFR2 p95 benchmark** — not separately measured (see NFR2 row); the guard is a single indexed predicate.
- **NFR4 pgvector composition** — forward-looking; lands with `ai-search-qna` (slice 6).
- **CI tripwire scope (T-005)** — scans `microservices/core/src` only; raw-`sql` snake-name access and aliased imports are documented, accepted v0.1 grep-tripwire gaps (see the test header).

## Downstream unblock

ADR-011 is **accepted** and the Option B mechanism is shipped and proven, so
`room-and-folders`'s document-bearing tasks (its T-006 onward — the first
tasks that persist/read customer documents) are **unblocked**: every new
tenant-scoped repo those tasks add is obtained through `scopedRepo(orgId)`,
classified in `tenancy.ts`, guarded by the T-005 tripwire, and covered by the
T-006 property test the moment its table joins the registry.
